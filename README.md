# بلک‌فرایدی سپکس

لندینگ کمپین بلک‌فرایدی سپکس به‌همراه فرم ثبت درخواست خرید، حمل و ترخیص و پنل کارشناس‌ها.

Next.js 16 · React 19 · TypeScript · Tailwind v4 · shadcn/Radix · SQLite (better-sqlite3) · SMS.ir

## قابلیت‌ها

- **لندینگ** (`/`): هیرو با ورودی لینک، شمارش معکوس، پیشنهادهای بلک‌فرایدی، روش کار، سه مسیر سفارش، فروشگاه‌ها به ترتیب اولویت (چین و امارات، بعد اروپا، آمریکا و ترکیه)، سؤالات متداول. سئو: متادیتا، تصویر OG، JSON-LD (Organization، WebSite، FAQPage)، sitemap و robots.
- **ثبت درخواست** (`/order`): سه مسیر «لینک کالا»، «عکس یا اسم کالا» و «فقط حمل و ترخیص»، چند کالا در یک درخواست، بارگذاری عکس/PDF، تأیید موبایل با OTP در آخر کار، کد پیگیری. پیش‌نویس فرم در sessionStorage می‌ماند. پارامترهای UTM و referrer ذخیره می‌شوند.
- **پیگیری** (`/track`): با کد پیگیری + شماره موبایل.
- **پنل** (`/admin`): لیست و جستجوی درخواست‌ها، «برمی‌دارم»، تغییر وضعیت، یادداشت و تاریخچه، تماس/واتس‌اپ/تلگرام، خروجی اکسل (CSV)، مدیریت پیشنهادهای لندینگ (با خواندن خودکار اطلاعات از لینک)، کارشناس‌ها و تنظیمات.
- **اعلان‌ها**: پیامک ثبت درخواست به مشتری و پیامک «درخواست جدید» به کارشناس‌ها (همه با هم یا به نوبت).
- **خواندن اطلاعات لینک**: بعد از ثبت درخواست، در پس‌زمینه از JSON-LD و Open Graph صفحه‌ی کالا (عنوان، تصویر، قیمت). ثبت درخواست هیچ‌وقت منتظر آن نمی‌ماند. برای فروشگاه‌های خارجی پراکسی لازم است: `FETCH_PROXY_URLS` (چند پراکسی با برچسب، مثل `US=http://…,NL=http://…`). همه هم‌زمان امتحان می‌شوند و اولین جواب درست برنده است؛ پراکسی برنده‌ی هر فروشگاه دفعه‌ی بعد زودتر شروع می‌کند. `npm run proxy:check` جدول فروشگاه × پراکسی را نشان می‌دهد.

## اجرا در محیط توسعه

```bash
cp .env.example .env.local   # SESSION_SECRET و ADMIN_PASSWORD را پر کنید؛ DATA_DIR را خالی بگذارید (./data)
npm install
npm run dev
npm run seed:dev             # اختیاری: چند کالای «نمونه» برای دیدن بخش پیشنهادها
```

بدون `SMSIR_API_KEY` پیامک‌ها فقط در لاگ چاپ می‌شوند و در محیط توسعه کد OTP در یک toast هم نمایش داده می‌شود.

```bash
npm run lint && npm run typecheck && npm test && npm run build
```

## استقرار روی سرور (aaPanel + nginx + Supervisor)

1. Node.js 20.9 یا بالاتر. پوشه‌ی داده را **بیرون** از پوشه‌ی پروژه بسازید: `mkdir -p /www/sepex-bf-data`.
2. کد را در `/www/wwwroot/sepex-bf` بگذارید و `.env` را از روی `.env.example` بسازید (`NODE_ENV` را در فایل نگذارید).
3. `npm ci && npm run build` (حتماً بعد از تنظیم `NEXT_PUBLIC_SITE_URL`). بیلد به دیتابیس دست نمی‌زند.
4. nginx: `deploy/nginx.conf.example`. Supervisor: `deploy/supervisor.conf.example`.
5. اولین ورود به `/admin` با `ADMIN_USERNAME` / `ADMIN_PASSWORD`. بعد از ورود، در «کارشناس‌ها» رمز را عوض کنید و کارشناس‌ها را با شماره موبایل اضافه کنید.
6. در «تنظیمات» زمان شروع/پایان کمپین و راه‌های ارتباطی را تنظیم کنید و «وضعیت سرویس‌ها» را چک کنید.

پشتیبان‌گیری: کل پوشه‌ی `DATA_DIR` (فایل `app.db` و پوشه‌ی `uploads`). برای کپی امن در حال اجرا: `sqlite3 app.db ".backup backup.db"`.

## قالب‌های پیامک SMS.ir

چهار قالب در پنل SMS.ir بسازید و شناسه‌ها را در `.env` بگذارید. اسم پارامترها قابل تنظیم است (پیش‌فرض‌ها در `.env.example`).

می‌شود دو حساب SMS.ir را کنار هم تعریف کرد: حساب اول با متغیرهای `SMSIR_*` و حساب دوم با `SMSIR_B_*`. اینکه پیامک‌ها از کدام حساب بروند، در «تنظیمات» ← «حساب ارسال پیامک» انتخاب می‌شود و فوراً اعمال می‌شود. همان‌جا اعتبار هر حساب دیده می‌شود و می‌توان پیامک آزمایشی فرستاد.

| قالب | پارامترها | نمونه‌ی متن |
|---|---|---|
| کد تأیید | `CODE` | کد تأیید سپکس: #CODE# |
| ثبت درخواست (مشتری) | `NAME`، `CODE` | #NAME# عزیز، درخواست شما در بلک‌فرایدی سپکس ثبت شد. کد پیگیری: #CODE# |
| درخواست جدید (کارشناس) | `CODE`، `NAME`، `METHOD` | درخواست جدید #CODE# از #NAME# (#METHOD#). پنل را ببینید. |
| هشدار پیگیری | `COUNT`، `CODE` | #COUNT# درخواست بیش از یک ساعت بی‌پاسخ مانده؛ قدیمی‌ترین: #CODE# |

## پیشنهادهای خودکار لندینگ

- **استخر کالا:** کالاهای منتخب (seed اولیه در `src/lib/deals.ts`) یا کالایی که کارشناس با تیک «به صف انتشار خودکار برود» اضافه کند.
- **هر ۲ ساعت** کالای بعدی صف (اگر ناموجود نباشد و عکس داشته باشد) روی لندینگ می‌رود؛ دسته‌ها به نوبت.
- **هر ۳۰ دقیقه** قیمت، قیمت خط‌خورده و موجودی از خود صفحه‌ی کالا خوانده می‌شود. ناموجود → پنهان؛ موجود شدن دوباره → برمی‌گردد. اگر فروشگاه جلوی بررسی را بگیرد فقط «بررسی نشد» می‌خورد و چیزی پنهان نمی‌شود.
- **لینک اختصاصی** هر کالا: `/d/<code>` — فرم سفارش با کالای پرشده در مرحله‌ی اطلاعات تماس باز می‌شود. کلیک‌ها (بدون ربات‌های پیش‌نمایش لینک) و سفارش‌ها (`utm_campaign = deal-<code>`) کنار هر کالا شمرده می‌شوند. `?s=telegram` منبع دیگری ثبت می‌کند.
- **استوری ۹:۱۶** از دکمه‌ی استوری کنار هر کالا، در مرورگر ساخته و PNG دانلود می‌شود. درصد تخفیف فقط اگر از سایت خوانده شده، در بررسی امسال تأیید شده یا دستی وارد شده باشد نشان داده می‌شود.
- خاموش کردن کل کارهای پس‌زمینه‌ی این بخش: `DEALS_DISABLED=1`.

## ساختار

- `src/content/landing.ts`: همه‌ی متن‌های لندینگ.
- `src/lib/catalog.ts`: کشورها، فروشگاه‌ها، دسته‌ها، وضعیت‌ها.
- `src/lib/db.ts`: اسکیما و مایگریشن‌ها (`PRAGMA user_version`؛ مایگریشن منتشرشده را ویرایش نکنید، مایگریشن جدید اضافه کنید).
- `src/lib/requests.ts`: ثبت درخواست، اعلان‌ها، خواندن لینک‌ها.
- `src/lib/safe-fetch.ts`: دریافت امن لینک‌های کاربر (جلوگیری از SSRF).
